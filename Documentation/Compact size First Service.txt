# Architecture

Zenith is being built as a **microservice/distributed system**, not a monolith.

Planned services:

```text
API Gateway
Market Data Service
Security Service
Indicator Service
Screening Service
Analysis Service
```

Each service should have its own responsibility and internal implementation.

**Do not directly import another service's internal classes.**

For example, Indicator Service should NOT directly import Market Data Service repositories.

Instead:

```text
Indicator Service
      ↓
Market Data Service API
      ↓
Market Data Database
```

Each service should own its own database/schema when persistent storage is required.

Do not create a root-level shared Alembic system.

Avoid unnecessary files/abstractions. Files should have meaningful responsibilities.

# Critical Database Rule

A Market Data record is uniquely identified by:

```text
symbol + datetime
```

**NOT:**

```text
symbol + datetime + interval
```

Example:

```text
AAPL + 2026-09-25 10:30
```

is one record.

If the same symbol/time arrives with another interval, update the existing row rather than creating another row.

`interval` is stored as a normal field and is updated during upsert.
